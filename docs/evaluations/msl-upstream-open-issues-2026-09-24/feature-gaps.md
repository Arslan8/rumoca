# What ModelSan needs for this upstream corpus

These are source-based capability assessments against the current dirty working tree, not promised detection rates. [Every issue](index.md) maps to a gap or an explicitly nonnumerical/unresolved disposition. The six [OMC-confirmed issue patterns](focused-results.md) have **no credited ModelSan detection** because the relevant execution paths are blocked. Other issues were not executed in this evaluation.

## Current implementation boundary

The [default registry](../../../packages/modelsan/modelsan/sanitizers/__init__.py) includes DomainSan, NumericSan, RangeSan, SolverSan, AssertSan, DiscontinuitySan, SingularitySan, InitSan, EventSan, ZenoSan, PhysicalSan and DivisorSan. DimensionSan, InitStaticSan, NetworkSan and StructureSan were additionally enabled in the focused probes. DeterminismSan/DifferentialSan need comparative runs and were not exercised here.

- [DomainSan](../../../packages/modelsan/modelsan/sanitizers/domain.py) targets supported scalar domain operations, including division, logarithms, square root and inverse trigonometric domains. This is not a comprehensive function, array-bounds, recursion or accuracy checker. Internal solver trial failures must be distinguished from accepted trajectory failures.
- [NumericSan](../../../packages/modelsan/modelsan/sanitizers/numeric.py) detects observed nonfinite values. A finite but wrong temperature, phase or quantization level needs another oracle. [RangeSan](../../../packages/modelsan/modelsan/sanitizers/range.py) relies on available declared limits; it does not invent intended physical/API bounds.
- [DimensionSan](../../../packages/modelsan/modelsan/sanitizers/dimension.py) means physical SI dimensions, **not array shape**. It checks additive/relational operand dimensions, propagates multiplication/division and derivatives, and treats unknown units/literals conservatively. It does not comprehensively validate assignments, powers, functions, conversion factors or intended quantity definitions. Thus the many unit issues are not automatically detected.
- [StructureSan](../../../packages/modelsan/modelsan/sanitizers/structure.py) and [SingularitySan](../../../packages/modelsan/modelsan/sanitizers/singularity.py) provide structural/simple algebraic candidates. Matching cannot prove a Jacobian well-conditioned or full numerical rank. [InitStaticSan](../../../packages/modelsan/modelsan/sanitizers/init_static.py) is not a replacement for source-level state-selection and nonlinear initialization semantics.
- [DiscontinuitySan](../../../packages/modelsan/modelsan/sanitizers/discontinuity.py) supplies conditional-threshold hints; it is not proof of the smoothness order claimed by `smooth(n, ...)`. EventSan/ZenoSan concern event activity, not correct logic, priority or sampling history.
- [NetworkSan](../../../packages/modelsan/modelsan/sanitizers/network.py) requires appropriate synchronized connector observations and correctly scoped boundaries. It cannot infer missing kinetic energy, arbitrary support frames, or all thermodynamic identities. [PhysicalSan](../../../packages/modelsan/modelsan/sanitizers/physical.py) uses component contracts/roles, not a universal rule that enthalpy, position or every parameter must be positive.
- [Pipeline.run](../../../packages/modelsan/modelsan/pipeline.py) depends on backend preparation, can stop early, and executes nominal/supplied cases. Producing boundary hints does not itself generate and execute an adaptive witness search. Our separate static pass exposes available findings even when the backend fails; it does not fabricate runtime coverage.
- [Trace comparison](../../../packages/modelsan/modelsan/sanitizers/comparison.py) currently pairs arrays by index without aligning the right-hand time grid. Its default relative scale is not an upstream regression oracle. Fix this before using differential disagreements as a bug-recall metric.

## Precision controls exposed by this evaluation

The BooleanPulse cases have `width=50`, but InitSan warns about an apparent `start=0` below the positive bound on both the passing and failing OMC controls. The warning does not distinguish the phase defect. Quantization similarly reports default start values for bound parameters whose actual bindings are `bits=2`. These need binding-aware triage before being called initialization bugs.

The quantization static pass also proposes `resolution=0` although the nominal dependent resolution is 0.5. Whether a parameter can be independently overridden must be checked against its declaration and dependency constraints; such a witness does not demonstrate the reported five-level defect. Network boundary/incomplete-observation messages likewise carry no detection credit.

For disputed reports, an oracle must not bake in the accusation. Examples: #1225 permits negative enthalpy by reference convention, #4724 permits signed length, #4770 compares different interpolation/smoothing methods, and #4801 passes interpolation smoothness at table construction. These are useful negative controls for precision, not automatic misses.
