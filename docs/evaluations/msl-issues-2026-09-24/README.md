# MSL issue detection evaluation — 2026-09-24

Scope clarification: this is a **local-report regression audit**, not the
requested evaluation of upstream GitHub issues. The corrected upstream work is
[tracked separately](../msl-upstream-open-issues-2026-09-24/README.md).

**The static analyzers rediscover the known arithmetic issues well, but the
current system cannot yet reliably execute and verify them end to end.** The
largest practical gaps are bitcode/runtime correctness, legal witness
generation, and campaign orchestration—not simply a shortage of sanitizers.

This evaluates **all locally documented MSL issues in the latest reviewed
ledger**, plus the five independent LLM reports. It does not enumerate the
upstream GitHub issue tracker or claim to cover every possible MSL defect.
No production code was changed by this evaluation.

## Results

| Measurement | Result | Interpretation |
|---|---|---|
| Fresh original-model analysis | **255/255 models**, covering **5,476 executable report instances** | All compiled and all enabled static/hint operations completed; no compiler/analyzer errors or timeouts in this sweep. |
| Historically confirmed reports | **809 exact static matches; 10 ambiguous source-identity matches; 0 with no same-target candidate** out of 819 | The 10 older BUG reports lack sufficient source ownership for strict automatic matching. These counts are report instances, not 819 unique bugs. |
| Historical false-positive/non-defect controls | **328 exact candidate re-emissions** out of 3,321 | 284 illegal witnesses, 8 assertion cases, 3 compound-denominator contract errors, and 33 machine-resistance cases needing policy/re-adjudication. Do not call all 328 newly verified false positives. |
| Seeded runtime evaluation | **315 cases / 124 models / all 819 confirmed report IDs accounted for** | 159 cases blocked in preparation, 93 blocked by nominal failure; only 63 reached a valid nominal-plus-trigger attempt. |
| Runtime evidence from those 63 attempts | **24 native operation signals; 39 generic pre-observation numerical failures** | Native signals are backend-anchored, not exact source-site rediscovery. Generic failure does not identify the bad denominator. |
| Independent LLM challenge set | **4/5 root causes, 5/7 variants identified statically** | Both CriticalDamping variants remain unresolved; all seven have correct zero hints. |
| Fresh independent OMC controls | **7/7 nominal-success / exact-source-trigger-failure pairs** | Newly rerun against local MSL 4.1.0. Only FirstOrder gets exact reached-denominator evidence from the native runtime in this challenge set. |

The runtime cases were **seeded with known triggers**. The current pipeline
collects hints but does not automatically schedule them. Static rediscovery,
seeded runtime signals, and independent verification are different claims.
The historical corpus was largely generated by these same detector families,
so these numbers are **not unbiased recall over all MSL bugs**.

## What should we work on next?

| Order | Work | Why |
|---|---|---|
| 1 | Repair fresh-bitcode validation/import and nominal execution failures | 252/315 seeded cases are blocked before a valid trigger test. Concrete failures include non-dense/missing domains, unknown imported coordinates, unsupported expressions and missing array observations. These are tool boundaries, not absent MSL rules. |
| 2 | Enforce legal witnesses using existing visibility metadata; preserve inherited `final` modifiers and trace back to legal public parameters | 284 historical illegal-witness candidates are re-emitted. Protected metadata is already present in a concrete missed-consumer case; a separate final-modifier example loses the flag before analysis. Do not suppress the legitimate public-parameter root cause. |
| 3 | Run static analyses even if backend preparation fails; connect hints to a bounded, legal testcase campaign | SignalPWM already has a valid static finding that the integrated pipeline discards on preparation failure. Correct hints alone do not execute tests. |
| 4 | Fix Boolean guard consumption and add structural source-rebuild/array-index obligations | CriticalDamping is the independent missed root cause: `normalized=True` is retained but mishandled; `n=0` also changes shape and invalidates `x[1]`. An artifact parameter override is not the same test. |
| 5 | Carry typed arithmetic faults from pre-solve binding evaluation into sanitizer diagnostics | Thyristor and many seeded cases fail before current Solve-row hooks. Preserve operation, operand, phase and source identity instead of only “non-finite result.” |

[Detailed priorities](features.md) also cover assertion handling, complete
domain-operation observations, Jacobian rank/conditioning, time-aligned
differential comparison, and targeted function contracts. Existing supported
zero/signed behavior must remain non-defect/advisory; blanket positivity rules
are not the solution.
